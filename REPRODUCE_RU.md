# Загрузка, проверка и повторение обучения

## 1. Проверить файлы без PyTorch

Из корня этого репозитория:

```bash
python3 verify.py
python3 -m unittest discover -s tests -v
```

[Список файлов](inventory.json) фиксирует SHA256 и размеры. Это проверка целостности
относительно опубликованного списка, не подпись независимой стороны и не
доказательство научных выводов. Служебные `.git`, `__pycache__`, виртуальные
окружения и рабочий каталог `work/` не входят в список.

Исторические JSON, архивы исходников и снимки весов не перезаписываются.
[Описание проверок и их границ](evidence/VALIDATION_SCOPE.md).

## 2. Среда и непроверенные условия переноса

Фактическое обучение: Python 3.11, PyTorch 2.13.0, NumPy 1.26.4,
macOS на M2 Pro, нейронные вычисления float32 через MPS.

Использованные версии дополнительных зависимостей перечислены в
[setup_manifest.json](source/research/bitseq_mps/setup_manifest.json) и
[requirements-observed.txt](requirements-observed.txt). В пакет включены именно
72 Python-файла исходной зафиксированной версии torchgfn; установка любой
версии с названием `torchgfn==2.4.1` не доказывает совпадение кода.

Остальные библиотеки не скопированы в пакет. Нужны, в частности,
`einops`, `tensordict`, `torch-geometric`, `psutil` и их зависимости;
часть модулей torchgfn импортируется сразу при загрузке пакета.

Список наблюдавшихся версий **не является проверкой чистой установки** на любой
платформе. Новую установку всех библиотек заново при упаковке не выполняли.
Не менять версии рабочего общего окружения; при необходимости создать отдельное.

Локальные проверки использовали существующий Python и прежний каталог
дополнительных библиотек, но сами `bitseq`, `tdlm` и `gfn` импортировались из
этого пакета. [Результат повторной оценки весов](evidence/VERIFICATION.json)
и [журнал тестов экспортированных исходников](evidence/exported_suite_final.log)
фиксируют выполненные проверки. Переносимость не следует из прежнего абсолютного
пути к окружению.

Монитор ресурсов исходного обучающего скрипта использует macOS `sysctl`.
Поэтому загрузка весов и оценка на CPU — не то же утверждение, что работоспособность
всего обучения на Linux. Linux-перенос требует отдельной адаптации и проверки
монитора; не отключать его молча ради запуска.

## 3. Загрузить и заново оценить принятые модели

Для совместимого окружения:

```bash
export PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=1
export PYTHONPATH="$PWD/vendor:$PWD/source/research/bitseq_mps:$PWD/source/src${PYTHONPATH:+:$PYTHONPATH}"
python verify.py --neural --device cpu
BITSEQ_BASE_REPLAY_GATE=1 python -m pytest source/research/bitseq_mps/tests tests -q
```

Первая команда:

- проверяет байты по списку файлов, архивы и зафиксированные исходники;
- читает состояния Adam у 13 конечных этапов, по 30 состояниям параметров;
- создаёт архитектуру и загружает принятые веса моделей 100, 101 и 102;
- заново вычисляет предсказания во всех 15 625 частичных состояниях;
- суммирует вероятности всех 4096 результатов под двумя заданными декодерами;
- проверяет критерии калибровки и расхождение с сохранёнными MPS-таблицами.

Модель не обучается, состояние оптимизатора не продолжается.
Известный ошибочный счётчик модели 100 **не исправляется** при оценивании.

Явные допуски сравнения CPU с исходными MPS-результатами:

| Сравниваемая величина | Допустимая максимальная абсолютная разница |
|---|---:|
| Таблица логарифмов вероятностей слов | $10^{-4}$ |
| Итоговые скалярные метрики | $10^{-5}$ |
| Вероятность отдельного полного результата | $10^{-6}$ |

Команда выводит и фактические различия. Допуск не выдаётся за наблюдаемую ошибку.
[Численный результат](evidence/VERIFICATION.json) содержит значения для всех трёх моделей;
[описание проверки](evidence/VALIDATION_SCOPE.md) различает предварительные и финальные
составы пакета. Количество файлов нужно читать из текущего `verify.py`/списка,
а не из более раннего результата проверки.

Вторая команда выполняет тесты: точные распределения против явного перечисления
путей; функции потерь и градиенты; восстановление снимка; короткую последовательность
обновлений с выборочными и условными метками и снижением скорости.
Это не ещё одно полное обучение на 12 500 шагах.

Пять [файлов этих тестов](source/research/bitseq_mps/tests/) добавлены при упаковке
и не относятся к историческому архиву исходников. Их
[происхождение и SHA256](evidence/VALIDATION_TEST_PROVENANCE.json) сохранены.
Если MPS отсутствует, соответствующий тест пропускается, не засчитывается как
успешная проверка устройства. Один тест обучающего скрипта использует macOS-монитор,
поэтому работоспособность всего набора на Linux не обещана.

Минимальная загрузка [модели 101](artifacts/BS-independent-base101/soft-low/ckpt_000500.pt):

```python
import torch
from bitseq.model import make_denoiser

checkpoint = torch.load(
    "artifacts/BS-independent-base101/soft-low/ckpt_000500.pt",
    map_location="cpu",
    weights_only=True,
)
model = make_denoiser(101)
model.load_state_dict(checkpoint["model"], strict=True)
model.eval()
logits = model(torch.tensor([[5, 4, 4, 4, 4, 4, 4]]))[:, 1:]
assert logits.shape == (1, 6, 4)
```

При использовании как замороженной модели сравнения фиксировать фактические веса
и полный SHA256. Не заменять её распределение $p_0$ идеальным
$q_{\mathrm{pre}}\propto e^{-d}$.

Если нужен новый вариант обучения из снимка, загрузить его состояние заново
или глубоко скопировать словарь оптимизатора. Повторное использование одного
изменяемого словаря между вариантами привело к дефекту модели 100.
При намеренном продолжении её исходного состояния явно учитывать `step=16500`.

## 4. Повторить фиксированный протокол моделей 101 и 102

[Исходники](source/) сохраняют байты членов
[архива реально использованного кода модели 101](artifacts/BS-independent-base101/source_snapshot.zip).
Дополнительные тесты обозначены отдельно. Расположение каталогов сохранено:
исходный [скрипт](source/research/bitseq_mps/checks/reproduce_base.py) вычисляет
корень из относительного положения файла.

Проверка плана не запускает обучение и не создаёт снимок модели:

```bash
python source/research/bitseq_mps/checks/reproduce_base.py plan \
  --seed 101 --out "$PWD/work/base101" --storage-root "$PWD/work"
```

Запуск на совместимом **Mac**, только если требуется реальное новое обучение:

```bash
python -u source/research/bitseq_mps/checks/reproduce_base.py run \
  --seed 101 --out "$PWD/work/base101" --storage-root "$PWD/work" --device mps
# Для seed 102 указать другой, ещё не существующий каталог вывода.
```

Последовательность: 6 000 обновлений с выборочными метками, 6 000 с условными
распределениями меток, 500 с теми же условными метками при меньшей скорости;
batch 256. Принятие только по последнему снимку. Если критерии не выполнены,
не выбирается «самый близкий» промежуточный снимок.

Скрипт проверяет исходники, SHA256 родителя, реальные счётчики Adam и число
пройденных шагов/примеров. Для указанного рабочего каталога действует предел
артефактов 2 GiB. Перед запуском нужны не менее 10 GiB свободного диска,
нормальное давление памяти, рост swap не больше 1 GiB и память процесса
RSS не больше 2 GiB. Один собственный нейронный запуск одновременно.

Побитовое совпадение полного длинного MPS-запуска не обещано. Во время упаковки
новое полное обучение не выполнялось; модели 101 и 102 — уже завершённые реальные
запуски, их файлы и журналы включены.

[Исторический диагностический скрипт модели 100](artifacts/BS-calibration-diagnostic/source_snapshot.zip)
сохранён для аудита, **не** предлагается как безопасный новый контроль четырёх
вариантов с одинаковым состоянием Adam. Комментарии и старые протоколы в архивах
могут предшествовать обнаружению ошибки. Текущая карточка и аудит имеют приоритет
над их формулировками об одинаковых протоколах.
